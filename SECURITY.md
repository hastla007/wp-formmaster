# Sicherheitsrichtlinie / Security policy

## Unterstützte Versionen / Supported versions

| Version | Sicherheitsupdates |
|---|---|
| 1.x (aktuelle Minor-Version) | ja |
| ältere Minor-Versionen | nein – bitte aktualisieren |

## Schwachstelle melden / Reporting a vulnerability

Bitte melden Sie Sicherheitslücken **nicht** im WordPress.org-Forum oder in öffentlichen Issues, sondern vertraulich an:

**`[SECURITY-KONTAKT]`** *(eigene `security@…`-Adresse, Entscheidung Nr. 15 – Adresse wird vor dem ersten Release eingetragen)*

Please report security issues privately to the address above, not in the public support forum or issue tracker.

Hilfreich sind: betroffene Version, Schritte zur Reproduktion, erwartete und tatsächliche Wirkung. Senden Sie keine echten personenbezogenen Daten.

## Ablauf / Process

1. Eingangsbestätigung innerhalb von 3 Werktagen.
2. Ersteinschätzung (Schwere, betroffene Versionen) innerhalb von 10 Werktagen.
3. Fix mit Regressionstest und Release; im Changelog unter „Sicherheit“ ohne Exploit-Details.
4. Koordinierte Veröffentlichung spätestens 90 Tage nach Eingang oder mit dem Fix-Release; Nennung des Meldenden auf Wunsch.

Die Fristen sind ein Vorschlag bis zur Bestätigung durch die Produktverantwortung (docs/BETRIEB.md, Abschnitt 2.6).
